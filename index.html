About

I care about the last mile between insight and action.

A model is only useful when it changes a decision, fits into the workflow around it, and fails in ways people can understand. That is the layer I like working in: context, interfaces, constraints, and the careful handoff from recommendation to execution.

I have worked as a Data Analyst at Dayforce and as a Data Scientist for Catholic Crosscultural Services and The BRIDGE, turning messy data and ambiguous goals into decisions, dashboards, models, and practical AI workflows.

I prefer small, readable systems with explicit tradeoffs: clear data flow, narrow automation boundaries, and enough observability to know when the system should pause instead of pretending to be certain.

Featured system

David

In active use

An AI executive assistant that connects long-running goals with weekly planning, calendar context, and approval-gated scheduling.

Problem

Planning breaks when goals live in one place, the calendar lives somewhere else, and daily decisions happen under pressure. David exists to keep those layers in conversation.

What exists
  • Telegram conversational interface
  • Google Calendar context injection
  • Approval-gated calendar writes
  • Session-aware memory
  • Recurring check-ins
  • Decision logs grounded in weekly state
Design choices

David separates suggestion from execution. Calendar writes require explicit approval, memory is scoped around useful continuity, and live calendar context keeps recommendations grounded in actual time constraints.

How I build

The stack matters less than the boundary.

I like tools that make the system easier to reason about. The important decisions are usually about what context enters the model, what actions it can take, what gets logged, and when a human needs the final say.

Context before automation

Assistants should know the relevant goal, state, and constraint before they suggest an action.

Gemini · LLM ops · prompt design · tool use

Approval before side effects

If a system can change calendars, send messages, or affect a workflow, the control surface has to be explicit.

FastAPI · Telegram · Google APIs · webhooks

Evaluation where it counts

Models and dashboards need checks that match the decision they support, not just metrics that look tidy.

Python · R · PyTorch · scikit-learn · forecasting

Small systems stay legible

I prefer deployment choices that are easy to inspect, recover, and maintain without hiding simple problems behind ceremony.

AWS Lightsail · PostgreSQL · Backblaze B2 · webhooks
